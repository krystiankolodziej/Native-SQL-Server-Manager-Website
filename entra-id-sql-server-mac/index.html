Signing in to Azure SQL with Microsoft Entra ID from a Mac

Entra ID is where corporate SQL Server access has been heading for years, and it is the one place where a Mac is at no disadvantage at all — provided the client can carry out a proper OAuth sign-in rather than pretending a password is enough.

Four ways in, and when each one fits

“Entra ID authentication” is a family of flows, not a single one. Native SQL Server Manager supports four, and the difference between them is mostly about where the sign-in happens.

Interactive browser sign-in

The default, and the one to reach for first. The app opens Microsoft’s own sign-in page; you authenticate there, complete whatever second factor your tenant asks for, and the app receives a token. Nothing about your password or your MFA method passes through the database client, which is exactly the property a security team wants to hear about.

Device code

The app shows a short code and a URL. You open that URL in any browser — on the same Mac, on your phone, on a machine that is allowed to reach the sign-in page — type the code, and finish there. This is the flow that saves the day when an embedded browser is blocked by policy, when the machine has no browser available, or when you are connected over a session where opening a window is awkward.

Username and password

A direct sign-in with an Entra ID account. It is the simplest to explain and the most limited in practice: tenants that enforce multi-factor authentication or conditional access will reject it, by design. Useful for accounts deliberately exempted from those policies, and little else.

Service principal

An application identity rather than a human one — an application ID and a secret. This is the right answer for shared workstations, scheduled work, and anywhere you would otherwise be tempted to leave a personal account signed in.

Azure SQL, Managed Instance and on-premises

Entra ID sign-in is most often associated with Azure SQL Database and Azure SQL Managed Instance; the former works exactly as you would expect, and so does the latter when reached through the gateway. It is worth remembering that the rest of the app does not change shape when the server is in Azure: the objects explorer, the schema-aware editor, in-grid editing and the export formats behave identically whether the server sits in a data centre in Ireland or under someone’s desk.

Encryption is not an afterthought here either. The connection dialog carries Encrypt connection and Trust server certificate as explicit choices, so reaching a cloud database does not quietly become a decision someone else made for you.

What this replaces

The usual macOS path to Entra ID authentication has been an ODBC driver plus an authentication library plus a configuration file, with a browser flow bolted on at the end. When it works it is invisible; when it does not, the error surfaces several layers below the tool you are actually using. Speaking TDS directly removes those layers: the app performs the OAuth flow itself and puts the resulting token on the wire.

Passwords and secrets that you ask the app to remember are kept in the macOS Keychain, not in a settings file next to your queries.

Questions

Does Entra ID sign-in to Azure SQL work with multi-factor authentication?

Yes. Interactive browser sign-in and device code sign-in both hand the challenge to Microsoft's own sign-in page, so whatever second factor your tenant requires — authenticator app, hardware key, conditional access — is handled there rather than by the database client.

What is device code sign-in and when should I use it?

Device code sign-in shows a short code that you type into a Microsoft sign-in page in any browser, including one on another machine. It is the practical choice when a browser cannot be opened on the machine running the client, or when a tenant policy blocks the embedded sign-in flow.

Can I connect to Azure SQL with a service principal?

Yes. A service principal signs in with an application ID and secret rather than a human account, which suits scripted or shared workstation use where interactive sign-in is not wanted.
