Azure Data Studio alternatives for the Mac, after the retirement

Azure Data Studio reached end of support on 28 February 2026. For Mac users it was the obvious cross-platform answer for years, which makes its absence more disruptive here than on Windows — where SSMS was always waiting.

What actually happened

Microsoft announced the retirement a year ahead, in February 2025, and carried it out on 28 February 2026. Nothing stops working the day after: an installed copy still launches and still connects. What ends is maintenance. There are no further releases, no security fixes, and no support case to open when something breaks. For a tool that holds credentials to production databases, “still runs” and “still advisable” are not the same statement.

Microsoft’s own recommendation is Visual Studio Code with the MSSQL extension, and it is a reasonable one — queries, scripts and database projects carry over. Not everything does: the MSSQL extension has since gained SQL Notebooks, but the dashboard and insight widgets have no equivalent.

The options on macOS

Visual Studio Code with the MSSQL extension

The supported path, and the right default if you already live in VS Code. You get a SQL editor, connections and a results grid inside an editor you know. It is an Electron application, so it carries the memory and launch characteristics that implies, and object administration is shallower than either SSMS or a dedicated client.

DBeaver

Free, open source, and covers an enormous range of database engines. That breadth is the trade: it runs on Java, its interface belongs to no platform in particular, and SQL Server is one of dozens of engines it reaches through a JDBC driver rather than a protocol of its own.

TablePlus

Fast, pleasant, and genuinely native on macOS. It is built around many engines rather than one, so its SQL Server support is broad rather than deep — the object tree does not go where a SQL Server-specific tool can go.

A Windows VM with SSMS

Still the complete answer for administration — Agent jobs, replication, deep server configuration — and still a virtual machine you have to license, update and give several gigabytes of RAM to keep a query window open.

Where this app fits

Native SQL Server Manager is deliberately narrower than any of the above: one engine, one platform. It is written in Swift and AppKit, and it implements TDS — the SQL Server wire protocol — itself, so there is no runtime, no ODBC driver and no configuration file between you and the server.

Against Azure Data Studio specifically, three differences matter most in daily use:

  • Sign-in. SQL logins, Microsoft Entra ID in four flavours, Kerberos single sign-on with no password at all, and NTLM — chosen from a picker rather than assembled in a connection string.
  • The object tree. Every database on the server, expanded only when you ask, down to keys, constraints, indexes, dependent views and routine parameters — with scripting to CREATE and DROP for any of them, SELECT, INSERT, UPDATE and DELETE for tables, and ALTER for routines.
  • Behaving like a Mac app. It launches immediately, stays light on memory, and does not ask you to think about a runtime.

What it does not try to be: a notebook environment, a multi-engine client, or a replacement for SSMS’s administrative depth. If your day is Agent jobs and replication topology, keep the VM. If your day is queries, schema and data on SQL Server from a Mac, this is built for exactly that.

Questions

When was Azure Data Studio retired?

Microsoft retired Azure Data Studio on 28 February 2026, having announced the date in February 2025. Existing installations still launch, but the product receives no further updates, fixes or security patches, and support cases can no longer be opened for it.

What does Microsoft recommend instead of Azure Data Studio?

Visual Studio Code with the MSSQL extension. Existing queries, scripts and database projects carry over, though features specific to Azure Data Studio, such as its notebooks and dashboard widgets, do not.

Is there a native macOS alternative to Azure Data Studio?

Yes. Azure Data Studio and VS Code are both Electron applications, and DBeaver runs on Java. Native SQL Server Manager is written in Swift and AppKit and speaks the SQL Server wire protocol directly, so it needs no runtime and no ODBC driver.
